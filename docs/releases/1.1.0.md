# Hosted MCP 1.1.0: release and production verification

Programscape MCP 1.1.0 adds continuity for saved application progress and explicit company selection when an account
can access several plans. The hosted endpoint is `https://programscape.com/api/mcp`; existing clients receive the
deployed implementation there. Refresh a client's saved tool list if it has cached an older schema.

## Production save/read verification

A production verification run passed all 12 cases on October 25, 2026 in Pacific time (October 26 UTC), against
revision `082d782c5a06149e09f95ebcd153ebee145ea31c`, with reported runtime Node.js `v22.23.4`.
The [sanitized verification receipt](1.1.0-verification.json) is public here. The original workflow runs in
Programscape's application repository and requires repository access; it is not required to read this receipt.

The verifier used a disposable account provisioned by CI, then exercised the normal application session and OAuth
APIs against production. It checked:

- An authenticated empty account and the signed-in tool inventory.
- Named plan choices and refusal of a write without company selection when several plans were available.
- Saving application progress and receiving the changed-field receipt.
- Preserving the version and update time when an unchanged save was repeated.
- Reading the saved progress through a new OAuth grant, agreement with the website read, and an unchanged second plan.
- Refusing a stale-version save, and clearing a reported result while preserving other saved fields.

Cleanup also passed: both temporary plans were deleted, none remained, all test grants were revoked, both revoked
access tokens were refused, and the disposable authentication identity was removed. Backups follow the existing
retention policy.

This proves the tested production API persistence and selected-plan isolation. It does not test email delivery, a human
consent click, or the Claude owner-portal submission flow.
